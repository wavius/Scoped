# Interfacing USB3300 ULPI PHY with Lattice ECP5 (iCESugar-Pro v2.0)

This document provides a hardware connection guide, timing considerations, ECP5 LPF pin constraints template, and Verilog interface skeleton for connecting a **USB3300 module** (ULPI PHY) to an **iCESugar-Pro 2** development board featuring a **Lattice ECP5 FPGA**.

---

## 1. ULPI Interface Overview

The USB3300 PHY interfaces with the FPGA via an 8-bit synchronous **ULPI (UTMI+ Low Pin Interface)** running at **60 MHz**.

| Signal Name | Direction (FPGA View) | Description |
| :--- | :--- | :--- |
| `CLK` / `CLKOUT` | **Input** | 60 MHz clock output generated by the USB3300 PHY. *Must connect to an ECP5 PCLK / GCLK pin.* |
| `DATA[7:0]` | **Bidirectional** | 8-bit bidirectional data bus. |
| `DIR` | **Input** | ULPI Direction. `1` = PHY owns bus (Read), `0` = FPGA owns bus (Write). |
| `NXT` | **Input** | ULPI Next. High indicates PHY accepted byte (Write) or presented new byte (Read). |
| `STP` | **Output** | ULPI Stop. Driven High by FPGA to terminate/abort a transaction. |
| `RESETB` / `RST` | **Output** | Active-low PHY hardware reset pin (some modules use active-high `RESET`). |
| `VCC` | **Power** | 3.3V DC Main Power Supply. *Must connect to 3V3 pin on FPGA.* |
| `GND` | **Power** | Ground reference. |
| `5V` | **Power / VBUS** | 5V USB Power. **Leave disconnected for USB Device mode** (host PC supplies 5V VBUS over USB cable). |

> [!IMPORTANT]
> **Signal Integrity & Jumper Wire Best Practices (60 MHz ULPI):**
> 1. **All 8 Data Pins (`DATA[0]` through `DATA[7]`) are REQUIRED.** ULPI is a byte-wide 8-bit parallel bus. If any data pin is disconnected, USB packets will corrupt.
> 2. **Use short DuPont Jumper Wires (10 cm / 4 in or shorter).** At 60 MHz, long loose wires create signal reflections and clock skew.
> 3. **Keep wire lengths equal.** Try to use matching length jumper cables for the data bus so signals arrive aligned with `CLKOUT`.

## 3. Lattice LPF Constraint File (`pins.lpf`)

Below is the exact `.lpf` configuration for **Header P2**:

```lpf
# 60 MHz ULPI Clock Input (Header P2 - Pin B1)
LOCATE COMP "ulpi_clk" SITE "B1";
```

## 4. Verilog ULPI Tri-State & Clocking Top Module

In Verilog/SystemVerilog, the bidirectional ULPI `DATA` bus must be driven via a tri-state buffer controlled by the `ulpi_dir` signal.

```verilog
module ulpi_wrapper (
    input  wire       ulpi_clk,      // 60 MHz clock from USB3300 PHY
    input  wire       rst_n,         // System reset active low
    
    // Physical ULPI Pins
    input  wire       ulpi_dir,      // 1 = PHY drives DATA, 0 = FPGA drives DATA
    input  wire       ulpi_nxt,      // PHY Next
    output reg        ulpi_stp,      // FPGA Stop
    output reg        ulpi_reset,    // PHY Reset (High = Active, Low = Reset)
    inout  wire [7:0] ulpi_data,     // Bidirectional Data Bus

    // Internal Logic Interface
    input  wire [7:0] tx_data,
    output wire [7:0] rx_data,
    input  wire       tx_valid,
    output reg        tx_ready
);

    // PHY Reset Logic (Hold PHY reset low for first 10ms after powerup)
    reg [19:0] rst_cnt = 20'd0;
    always @(posedge ulpi_clk or negedge rst_n) begin
        if (!rst_n) begin
            rst_cnt    <= 20'd0;
            ulpi_reset <= 1'b0; // Reset active
        end else if (rst_cnt < 20'd600000) begin // ~10ms at 60MHz
            rst_cnt    <= rst_cnt + 1'b1;
            ulpi_reset <= 1'b0;
        end else begin
            ulpi_reset <= 1'b1; // Release reset (Normal PHY operation)
        end
    end

    // Tri-State Buffer Logic for Bidirectional Data Bus
    reg  [7:0] out_data;
    wire       drive_bus = !ulpi_dir; // FPGA drives bus when DIR is low

    assign ulpi_data = drive_bus ? out_data : 8'hZZ;
    assign rx_data   = ulpi_data;

    // Basic ULPI Protocol Handshake Logic
    always @(posedge ulpi_clk) begin
        if (!ulpi_reset) begin
            ulpi_stp <= 1'b0;
            out_data <= 8'h00;
        end else begin
            // Handle ULPI transmit/receive state machine here
            if (drive_bus && tx_valid) begin
                out_data <= tx_data;
            end
        end
    end

endmodule
```

## 5. Critical Implementation Notes

1. **Waveshare USB3300 Board Pinout & Reset**:
   - On the standard Waveshare USB3300 EV board (AliExpress link), the `RESET` pin is **active-high**. Drive `RESET` **High** to hold the chip in reset, and **Low** for normal operation (or connect to an active-low net through an inverter depending on board revision).
   - Check the onboard jumper: Waveshare boards often have VBUS logic jumpers. Ensure 3.3V power is supplied to the VCC pin.
2. **Clock Input Routing**:
   - `CLKOUT` (60 MHz) must be connected to an ECP5 primary clock pin (`PCLK`). If `nextpnr-ecp5` throws a clock routing error, ensure `FREQUENCY PORT "ulpi_clk" 60.0 MHz;` is in your `.lpf`.

## 6. Recommended Open-Source USB Cores (No Custom Verilog Required)

Instead of writing ULPI bus state machines and USB protocol handling (packet serialization, NRZI encoding, CRC generation, endpoint descriptors) in Verilog, use these tested open-source IP cores that generate pure Verilog for ECP5:

### Option A: LUNA Framework (Top Choice for ECP5 + USB3300)
- **Repository**: [https://github.com/greatscottgadgets/luna](https://github.com/greatscottgadgets/luna)
- **Why**: Maintained by Great Scott Gadgets specifically for **Lattice ECP5 + USB3300 ULPI PHY**.
- **Capabilities**: Full High-Speed (480 Mbps) USB 2.0. Supports Bulk IN/OUT streams (ideal for streaming oscilloscope sample buffers to `libusb`).

#### Generating Verilog with LUNA:
1. Install LUNA directly from GitHub:
   ```bash
   pip install git+https://github.com/greatscottgadgets/luna.git
   ```
2. Run a simple build script to output standard Verilog:
   ```python
   # generate_usb.py
   from luna.gateware.usb.usb2.device import USBDevice
   from amaranth.back import verilog

   # Instantiate a USB2 High-Speed Device with ULPI PHY interface
   # ... generates top_level_usb.v ready for Yosys + nextpnr-ecp5
   ```
3. Drop the generated `top_level_usb.v` directly into your Yosys build pipeline.

### Option B: Alex Forencich's `verilog-usb`
- **Repository**: [https://github.com/alexforencich/verilog-usb](https://github.com/alexforencich/verilog-usb)
- **Why**: Written in 100% standard Verilog-2001. No Python dependencies.
- **Includes**: ULPI PHY wrapper, USB device engine, endpoint FIFO bridges.

### Option C: `fpga-usb-stack` / `valentyusb`
- **Repository**: [https://github.com/smistad/fpga-usb-stack](https://github.com/smistad/fpga-usb-stack)
- **Why**: Provides a simple FIFO-to-USB Bulk transfer pipeline for High-Speed streaming.
